# Задание 7.I — геттеры и const-корректность

## 1. Геттеры

Геттеры добавлены для всех информационных полей класса `QuadrupedRobot`:

| Геттер | Возвращает | Почему |
|---|---|---|
| `getId()` | `const std::string&` | id нужен для идентификации (логирование, поиск) |
| `getName()` | `const std::string&` | полезно для отображения |
| `getBatteryLevel()` | `double` | заряд — ключевая информация о состоянии |
| `getCurrentCommand()` | `const std::string&` | полезно для отладки |
| `getTodayDistance()` | `double` | ключевая метрика работы |
| `getLast10()` | `const double*` | статистика за 10 дней; отдаётся **только на чтение**, чтобы внешний код не мог нарушить инвариант (неотрицательные дистанции) |
| `getDays()` | `int` (static) | размер массива-статистики |

Сеттеров нет для `id`: по условию он «недоступен для изменения».

## 2. Что должно быть const и почему

- **Все геттеры** (`const`-методы): они не изменяют объект, только читают. Это позволяет
  вызывать их для `const`-объектов и `const`-ссылок (например, при передаче объекта в
  функцию печати как `const QuadrupedRobot&`).
- **Ссылки, возвращаемые геттерами, — `const std::string&`**: наружу нельзя отдавать
  неконстантную ссылку, иначе внешний код смог бы изменить приватное поле в обход сеттеров
  (и нормализации).
- **`getLast10()` возвращает `const double*`**: защита владеемого массива от прямого
  изменения (нарушения инварианта «дистанции неотрицательны»).
- **`checkId()` — `const`-метод**: только проверяет поле, ничего не меняет.
- **Функции нормализации — `static`**: им не нужен доступ к объекту (работают с аргументом),
  поэтому не должны быть методами экземпляра.
- **`getDays()` — `static`**: возвращает константу класса, не зависит от объекта.
- **Сеттеры НЕ const** — по определению: они изменяют объект.
- **Параметры, принимаемые по константной ссылке** (`const std::string& n` и т.п.):
  функции не владеют строкой и не должны её менять; const-ссылка ещё и позволяет
  передавать временные объекты и avoids копирование.

Проверка: в `main.cpp` объявлен `const QuadrupedRobot& cr = r;` — вызов
`cr.getName()` компилируется, а попытка `cr.setName("X")` не компилируется
(ошибка: «cannot call non-const member function»).
