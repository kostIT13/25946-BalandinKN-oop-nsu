# Задание 7.III — main из примера (Book) и контейнеры

## 1. `robot_book.exe` — main по образцу примера с классом Book

Структура примера сохранена (см. `main_book.cpp`):

| Пример (Book) | Наш класс (QuadrupedRobot) |
|---|---|
| `Book::print_count()` | `QuadrupedRobot::print_count()` |
| `Book::class_name` | `QuadrupedRobot::class_name` |
| `Book b("...", "...", 500, 1939)` | `QuadrupedRobot r("R1", "Spot", 80.0, "walk", 5.0, arr)` |
| `b.printBook()` | `r.printRobot()` |
| `b.add_bookmark(222)` | `r.addDistance(2.0)` |
| `std::cout << b` | `std::cout << r` |

### Соответствие количества объектов и переменных

- `my_first_robot` — объект **#1**, живёт до конца `main` (1 переменная = 1 объект);
- `my_second_robot` — объект **#2**, создан конструктором копирования из #1 (1 переменная = 1 объект);
- во внутреннем блоке `{}` `my_third_robot` — объект **#3**: рождается и уничтожается внутри блока
  (количество объектов в блоке: 3; после блока: 2 — счётчик это подтверждает);
- всего создано 3 объекта, уничтожено 3 (2 в конце `main` + 1 в конце блока).

Копии независимы: `addDistance` у копии не меняет оригинал (у каждого свой массив `last10`).

## 2. `robot_containers.exe` — объекты в vector, list, set

В каждый контейнер добавлено 4–5 объектов:

```cpp
v.push_back(QuadrupedRobot(...));   // vector, 4 шт.
l.push_back(QuadrupedRobot(...));   // list, 5 шт.
s.insert(QuadrupedRobot(...));      // set, 4 шт. (нужен operator<)
```

### Анализ вывода

На каждый `push_back`/`insert` с временным объектом происходят **три события**:
1. `initialization constructor` — создание временного объекта-аргумента;
2. `copy constructor` — копирование временного объекта в контейнер;
3. `destructor` — уничтожение временного объекта (счётчик возвращается к значению до вставки).

Итого для 4 вставок в vector: 4 init + 4 copy + 4 dtor; то же для list (5) и set (4).

После вставок живых объектов ровно 13 (4 в vector + 5 в list + 4 в set) —
временные копии уничтожены, счётчик показывает только объекты в контейнерах.

При `clear()` вызываются деструкторы всех элементов (в порядке, зависящем от контейнера:
set — в порядке убывания ключа, list — в обратном порядке вставки, vector — с конца).
После очистки счётчик = 0: утечек нет, каждому `new[]` соответствует `delete[]` в деструкторе.
