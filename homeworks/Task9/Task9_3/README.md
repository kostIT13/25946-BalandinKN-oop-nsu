# Задание 9.III — вмещение объектов: композиция и агрегация

Класс-вместитель: **боевое отделение квадропедальных роботов**, 5–10 роботов
(границы проверяются конструктором). Показаны оба способа вмещения.

| Вариант | Класс | Хранение | Владение |
|---|---|---|---|
| Композиция | `RobotUnit` | `std::vector<QuadrupedRobot>` (по значению) | владеет: само создаёт и само уничтожает |
| Агрегация | `RobotSquad` | `std::vector<QuadrupedRobot*>` (указатели) | не владеет: только ссылается на чужих роботов |

Время жизни наблюдаемо: `QuadrupedRobot` ведёт счётчик живых объектов, и демо
печатает его на каждом шаге.

## Что видно в выводе демо

**Композиция** (`RobotUnit unit("Alpha", 6)`):

```
живых объектов: 6   (после создания отделения Alpha(6))
живых объектов: 12  (пока жива копия отделения)      <- копирование отделения = глубокая копия
uid оригинала[0] = 9, uid копии[0] = 14               <- разные объекты
живых объектов: 6   (копия умерла — её роботы умерли вместе с ней)
живых объектов: 7   (наружу отдана КОПИЯ робота #9, оригинал на месте)
живых объектов: 0   (после уничтожения отделения — роботов больше нет)
```

Роботы родились вместе с отделением и умерли ровно в его деструкторе. Отдать
наружу сам объект нельзя: `at()` и `retirementCopy()` возвращают только `const&`
и копию, указатель на элемент `vector` после выхода из блока был бы висячим.

**Агрегация** (роботы созданы внешним кодом, `RobotSquad` хранит указатели):

```
живых объектов: 3   (роботы созданы внешним кодом)
rover состоит в обоих: uid=21 (один объект, два отделения)
повторная запись отклоняется: отказ
command 'march' issued -> из ВТОРОГО отделения тот же робот: cmd=march
живых объектов: 3   (перед выходом из блока)
живых объектов: 3   (после уничтожения ОБОИХ отделений)  <- роботы пережили отделения
```

Плюс шаг C — цена этой свободы: `QuadrupedRobot*` на объект из внутреннего блока
остаётся после его смерти (висячий указатель). В демо он намеренно **не**
разыменовывается — чтение было бы неопределённым поведением.

## Отличия и последствия

| | Композиция | Агрегация |
|---|---|---|
| Время жизни вмещаемого | строго внутри времени жизни вместителя | независимое: вместитель может умереть раньше или позже |
| Владение | одно-единственное; робот не может быть в двух отделениях | общее; один робот может состоять в нескольких отделениях |
| Копирование вместителя | глубокое: копируются все роботы (дорого, см. 8.I) | поверхностное: копируется список указателей, роботы остаются общими |
| Опасность | почти нет: нельзя получить висячий указатель, чистить память не нужно | висячий указатель/запись, если робот умер раньше отделения |
| Инвариант «5–10 роботов» | держится конструктором | снаружи: отделение может быть пустым |
| Доступ к изменению | через методы отделения, наружу — только копия/const | общий объект меняют все, кто на него ссылается |

### Когда что выбирать

- **Композиция** — по умолчанию: часть «принадлежит» целому и без него не имеет
  смысла (роботы набраны самим отделением). Проще инварианты, нет ручного
  управления временем жизни, нет утечек и double free.
- **Агрегация** — когда объект существует независимо от контейнера и может быть
  общим для нескольких (робот зачислен в два отделения, робот живёт в парке
  техники, а отделения только ссылаются). Платой — обязанность внешнего кода
  гарантировать, что робот переживёт все ссылки на него.

В современном коде «агрегацию с общим владением» обычно делают через
`std::shared_ptr` (тогда робот умрёт, когда умрёт последняя ссылка), а «агрегацию
без владения» — через `std::unique_ptr` у владельца + сырые указатели/ссылки у
наблюдателей. Здесь оставлены сырые указатели намеренно: иначе не было бы видно
разницы во времени жизни, которую требует задание.
