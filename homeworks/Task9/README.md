# Задание 9 (docs/Задания ООП 09.pdf) — дружба и вмещение объектов

Каждая часть — самостоятельный cmake-проект со своей копией `QuadrupedRobot`.

| Часть | Папка | Что сделано |
|---|---|---|
| 9.I | `Task9_1` | п.1 — дружественная свободная функция `setManufacturer()`: доступ к одному приватному полю (`manufacturer`). п.2 — дружественный класс `RobotFactory` (`friend class`): доступ ко всем приватным полям, приватной статике (`objectCount`, `nextUid`) и приватным методам. Границы доказаны ошибкой компиляции (`not_allowed_example.cpp`) |
| 9.II | `Task9_2` | Класс `Administrator`, чьи **конкретные методы** объявлены друзьями (`friend void Administrator::setModel(...)`): один метод правит одно поле (`model`), другой — два (`id` + `model`), но не все; остальные методы видят только public-часть |
| 9.III | `Task9_3` | Отделение из 5–10 роботов двумя способами: `RobotUnit` (композиция, `vector<QuadrupedRobot>`) и `RobotSquad` (агрегация, `vector<QuadrupedRobot*>`), с наблюдением времени жизни через счётчик живых объектов и разбором отличий/последствий |

## Общий смысл трёх частей

Задача про объём доступа к приватному, от минимального к максимальному и обратно:

- **9.I п.1** — `friend` одной функции: доступ ровно к одному полю, лишнее закрыто языком.
- **9.II** — `friend` конкретным методам класса: доступ к 1–2 полям, остальной класс-«свой» его не получает.
- **9.I п.2** — `friend class`: доступ ко всему приватному; контроль инварианта перестал обеспечиваться языком и лёг на класс-друг.
- **9.III** — другой способ «знать о другом объекте»: не доступ к полям, а владение или ссылка на весь объект; у него ровно две степени силы — композиция и агрегация.

## Сборка

Все три части собираются одинаково (MinGW или MSVC), пример для 9.I:

```
cmake -S homeworks/Task9/Task9_1 -B homeworks/Task9/Task9_1/build -G "MinGW Makefiles"
cmake --build homeworks/Task9/Task9_1/build
homeworks\Task9\Task9_1\build\robot.exe
```

Файлы `not_allowed_example.cpp` в 9.I и 9.II в сборку **не** входят: это примеры
обращений к приватному из не-дружественного кода, они должны не собираться.
Проверка: `g++ -std=c++17 -fsyntax-only -I. not_allowed_example.cpp`

Подробности — в README каждой части.
